Documentación de CloudPulse

CloudPulse monitoriza tus servicios desde 14 regiones, te avisa cuando algo falla y publica el estado de tu infraestructura para tus clientes. Esta guía te lleva desde cero hasta tu primer monitor en producción.

Quickstart

Cuatro pasos para tener tu primer monitor corriendo.

  1. Crea una API key

    Desde el dashboard, ve a Settings → API Keys y genera una clave con permisos de escritura.

  2. Instala el CLI

    # macOS / Linux
curl -fsSL https://cli.cloudpulse.example.com/install.sh | sh

  3. Añade tu primer monitor

    cloudpulse monitors:create \
  --name "api-production" \
  --url "https://api.tuapp.com/health" \
  --interval 10s

  4. Verifica que está activo

    cloudpulse monitors:list

# NAME             STATUS       UPTIME
# api-production   operational  100.00%

Nota

El plan Starter incluye 5 monitores gratuitos con checks cada 5 minutos. Ver precios.

Autenticación

Todas las peticiones a la API requieren un header Authorization con tu API key:

curl https://api.cloudpulse.example.com/v1/monitors \
  -H "Authorization: Bearer cp_live_xxxxxxxxxxxx"

Atención

Nunca incluyas tu API key en código del lado del cliente. Trátala como cualquier otro secreto de producción.

Crear un monitor

Un monitor comprueba periódicamente un endpoint HTTP, TCP o DNS y registra latencia, código de respuesta y disponibilidad. Puedes crearlos desde el dashboard o mediante la API. 

{
  "name": "api-production",
  "type": "http",
  "url": "https://api.tuapp.com/health",
  "interval_seconds": 10,
  "regions": ["us-east", "eu-west"]
}

Configurar alertas

Cada monitor puede notificar a uno o varios canales cuando cambia de estado. CloudPulse soporta Slack, PagerDuty y webhooks genéricos. 

cloudpulse alerts:add \
  --monitor "api-production" \
  --channel "slack" \
  --target "#incidents"

Status pages

Cada cuenta incluye una status page pública, generada automáticamente a partir del estado de tus monitores. Puedes verla en funcionamiento en /status.

REST API

Base URL: https://api.cloudpulse.example.com/v1

MétodoEndpointDescripción
GET/monitorsLista todos los monitores
POST/monitorsCrea un monitor nuevo
GET/monitors/:idDetalle de un monitor
DELETE/monitors/:idElimina un monitor
GET/incidentsHistorial de incidentes

Webhooks

Recibe un POST en tu endpoint cada vez que un monitor cambia de estado:

{
  "monitor": "api-production",
  "status": "degraded",
  "timestamp": "2026-08-19T09:12:00Z"
}

Rate limits

La API permite 600 peticiones/minuto por API key. Las respuestas incluyen los headers X-RateLimit-Remaining y X-RateLimit-Reset.
